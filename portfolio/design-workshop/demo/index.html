Static build - read-only. This is the FWLB Design Workshop board served as files, with no authoring server behind it. Every lane, candidate, verdict, note, pass history, work-card, milestone and flow graph shown here is the recorded data, unedited. What the live board writes - verdicts, answers, re-render requests, work-cards, milestones, flow edits - is intercepted and refused with the reason, so nothing silently no-ops. what the live board does with these
  • Verdict (keep / tweak / kill plus a note) writes back into the lane's manifest.json and wakes an orchestrator agent, which dispatches a worker to act on the note. The verdicts here are the output of that loop having run for four passes.
  • Work-card pins a note to a specific frame of a clip, so a critique names a moment rather than a clip.
  • Request queues a re-render; a worker renders the candidate again and the board live-reloads over SSE when the new file lands.
  • Ask is the reverse channel - the agent's question waiting for an answer.
  • Flow diffs a hand-drawn intended scene graph against one extracted from the code and a runtime trace; edits to the intended graph are written back.
  • Clips are sampled. All candidate metadata ships; 28 of the rendered mp4s do, chosen to show the range of judgments rather than the best-looking results. The full set is 763 MB. A candidate without its clip is labelled in place.
